# Changelog

Notable changes to `tare.tools.agent-runtime` are recorded here, newest first.

## Unreleased

- `NativeSession` and `NativeContext` (0.14.12) extend read-compaction amnesia protection to pure read-only lookup sessions (capabilities within `read`, `list`, `search`, `context`, `research`, `report_signal`, such as planners, explorers, and auditors): when `max_stagnant_turns` is enabled and `MAX_READONLY_COMPACTIONS` (3) consecutive `context_activated` compactions occur without delivering (even with `max_compactions=None`), `NativeSession.run()` stops with `blocked` / `NO_PROGRESS`, while `NativeContext.prepare()` instructs read-only compaction summaries to retain inspected paths, symbol names, and line ranges so the next turn delivers directly instead of re-reading covered files. Multi-tool coordinator sessions and edit-capable sessions (`MAX_COMPACTIONS_WITHOUT_MUTATION = 3`) remain unchanged.
- `NativeSession` and `NativeContext` (0.14.11) guard write-capable sessions (`edit` in `capabilities`) against unbounded read-compaction amnesia loops: when `max_stagnant_turns` is enabled and 3 consecutive `context_activated` compactions occur without any succeeded mutating tool call (`edit`, `rename`, `command`, `terminal_write`, `terminal_run`, `write`, `delete`), `NativeSession.run()` stops with `blocked` / `NO_PROGRESS` (resetting the counter on any succeeded mutation, `user_message`, or `host_observation`, while leaving read-only sessions unaffected); and `NativeContext.prepare()` instructs edit-capable compaction summaries to preserve symbol names and line ranges so the next turn reads the minimal target span in larger chunks (up to 200 lines) and edits before re-reading other files.
- `NativeContext.prepare()` (0.14.10) admits a post-compaction turn whose token count crosses `trigger_limit` again while still fitting `hard_limit` once the latest compaction attempt succeeded and exhausted `max_compactions`, instead of blocking with `COMPACTION_BUDGET` while calls remain; turns above `hard_limit` and resumes after a failed or rejected compaction attempt still block with `COMPACTION_BUDGET`.
- `NativeContext.prepare()` (0.14.9) admits a request above the soft compaction trigger when there is no compactable history yet and the count still fits the hard input ceiling (`window - output_reserve - margin`), instead of blocking turn 0 with `NO_COMPACTABLE_HISTORY`; requests above the hard ceiling with no compactable history still block, and compaction still triggers as soon as compactable history exists.
- The pre-push hook now checks unpublished commits' author and committer emails via `tools/push_preflight.py`, refusing any non-GitHub-noreply address before pushing branches or tags (and cleanly ignoring an empty line forwarded by a hook wrapper).
- `max_model_retries` counts per call: a model call that returns resets the failure count, so a failure early in a long session no longer spends the retry of every later call. Two failures in a row still exceed one retry, and a resume still never resets the count (2026-11-09: a second slip of the AGY CLI blocked a TUI session because its first slip, calls earlier, had used the session's only retry).
- CI runs on GitHub-hosted Linux and Windows runners (`Tests (linux)`, `Tests (windows)`) with the README's install and test commands and a pip cache. The repository variables `CI_RUNNER_LINUX` and `CI_RUNNER_WINDOWS` move it to your own runners, and pull requests from forks then skip it.
- First public release. The repository starts from a single commit; earlier history is not published. It contains the
  bounded tactical agent-loop runtime that tare.tools.os hosts through the kernel's provider and process ports, and
  its test suite.
